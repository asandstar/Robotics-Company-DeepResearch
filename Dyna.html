01

How to Read This Report

Evidence strength 描述公开材料对某个窄 claim 的支持程度；它不回答谁执行了验证。External Corroboration 与 Independent Verification 因此保留为两个字段。Strong evidence 不等于 independently reproduced。

External Corroboration

外部数据集、公开活动、named customer 或独立报道可证实某些外部事实或场景；不自动验证完整指标。

Independent Verification

要求结果由独立主体按足够透明的协议检查或复现。当前 registry 中绝大多数 claim 为 No。

Company Thesis

Dyna 将规模化矛盾放在 physical economy：机器人真实交互数据稀缺、部署长尾失败昂贵，而人类第一视角视频提供更宽的物理活动覆盖。公开路线从单任务长期可靠性，逐步转向 human-video representation 与部署后 robot post-training 的组合。

Loop A · breadth

human egocentric video → pseudo-action / future-video objectives → transferable representation。

Loop B · grounding

task-specific robot data → physical post-training → deployment failures → 下一轮数据与恢复。

Two-loop interpretation · RI：这是研究归纳；Dyna 没有公开把路线命名为 “two-loop strategy”。

Data Engine

原始 data source 与 supervision type 是不同维度。部分 human video 经 3D hand-pose estimation 产生 wrist trajectory 与 thumb-index aperture pseudo-action；未通过 action 标注门槛的视频仍可训练 future-video objective。

Known

predominantly head-mounted human manipulation video；nested scale subsets；100-hour held-out human set；pseudo-action 与 video-only ablations；physical policy 后续使用 robot demonstrations。

Unknown

data partners、license inventory、deduplication、action-labeled fraction、hand-pose failure rate、demographics、annotation/estimation error、exact corpus composition。

不要误读：“pure video” ≠ no action-like supervision；“human-video pre-training” ≠ final physical policy never sees robot data。

Three Evidence Stages

Dyna-2 的证据不是一个单一 benchmark，而是从 human validation、held-out robot trajectory prediction 到 post-trained physical execution 的三级链条。每一级回答不同问题，数据输入、metric 与 physical meaning 也不同。

Why the chain matters. Stage A 测量 human-domain representation，Stage B 测量对未用于 pre-training 的 robot trajectories 的离线 action prediction，Stage C 才测量真机执行。Stage C 引入 robot demonstrations，因此它支持“pre-training scale improves a post-trained policy”，而不是“human video alone controls robots”。

09

World-Action Model Deep Dive

Dyna-2 将 video diffusion 与 action prediction 联合建模：modality-specific DiT streams 交换信息；flow matching 学习 future-video latents 与 future action chunks；proprioception 进入 action transformer，text cross-attends to video。

Video stream

Future prediction as representation learning

video tokens 使用 causal masking；text cross-attends into video。future-video flow 为动作学习提供关于物理变化的共享表征，但不等于规划器。

Action stream

State-conditioned action chunks

proprioception 进入 action transformer；action tokens 使用 bidirectional self-attention，并利用 observed video context 预测未来动作块。

Missing disclosure

Architecture remains only partially specified

未公开 parameter count、video latent codec、text backbone、context/horizon、control rate、normalization、training steps、compute、seeds 与 inference latency。

Training

observed context → two objectives

future-video objective + future-action objective → shared temporal / physical representation。

Inference

observation → action prediction

披露的 scaling-law action head 不生成、也不 attend predicted future video。

World Model ≠ Imagined-Video Planning

world-model training objective 学习未来预测表征；planning through imagined rollout 则需在推理时生成/评估候选未来。Dyna 的 main scaling policy 只公开支持前者。

Infrastructure Deep Dive

robot episode 同步多相机、proprioception 与 action，采样常需稀疏视频帧加密集 state/action window；这与独立图片或连续 token stream 的访问模式不同。

Why a robot sample is structurally different

一条训练样本可能只解码少量 camera frames，却需要更长、更密集的 state/action window；多个 modality 还带有不同 clock。随机 temporal access、同步与 calibration 因而成为数据格式的一部分。

Why WAM changes storage choices

稀疏 VLA sampling 会频繁支付 keyframe seek cost，较长的连续 WAM clip 则更能摊薄 GOP decode。policy context length 因此也会影响 codec 与 chunk layout。

Manifest as reproducibility object

manifest 不只是 path list，而是一次 run 精确使用的 episode range、位置与筛选结果。把它冻结并 memory-map，才能同时控制启动时间、sharding 与可复查性。

What internal numbers still omit

cold-cache behavior、完整 GPU-hours、node count、energy、failure distribution、checkpoint loss、annotation cost，以及每个 usable human-video hour 的总成本仍未公开。

Why Million-Hour Infrastructure Matters

Storage→Scheduler→Metadata→Network→Optimizer Communication→Reliability

1M hours 不只是“更多存储”。当一个瓶颈被移除，主成本移动到控制面、manifest、数据局部性、collective communication 或多周训练的故障恢复。单纯增加 GPU 无法修复随机读取、scheduler write burst、48 小时 manifest crawl 或远端 object-store latency。
